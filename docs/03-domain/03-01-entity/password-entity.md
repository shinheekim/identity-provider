# Password 엔티티

## 1. 개요

Password는 사용자의 비밀번호 및 인증 관련 보안 정보를 관리하는 엔티티이다.  
Identity와 연결되며, 주로 일반 로그인(LOCAL)에서 사용된다.

비밀번호 변경 이력, 로그인 실패 횟수, 계정 잠금 상태 등을 관리한다.

---

## 2. 테이블 정보

- 테이블명: `passwords`
- 설명: 사용자 비밀번호 및 인증 보안 정보 관리

---

## 3. 필드 정의

### 3.1 기본 식별 정보

- **id**
    - Password 고유 식별자
    - PK

- **identity**
    - 해당 비밀번호가 속한 Identity
    - Identity와 N:1 관계

---

### 3.2 비밀번호 정보

- **passwordHash**
    - 암호화된 비밀번호 값
    - 평문 저장 금지

- **passwordAlgo**
    - 비밀번호 암호화 알고리즘
    - 암호화 알고리즘을 변경을 할경우 추가한다.
    - 예
        - `bcrypt`
        - `argon2`
        - `scrypt`

---

### 3.3 변경 이력

- **passwordChangedAt**
    - 비밀번호 변경 시각
    - 비밀번호 정책 적용 시 기준값으로 사용

---

### 3.4 인증 실패 관리

- **failCount**
    - 로그인 실패 횟수
    - 현재 구현 기준 5회 연속 실패 시 계정 잠금

---

### 3.5 계정 잠금

- **lockedUntil**
    - 계정 잠금 해제 시각
    - 해당 시간 이전에는 로그인 불가
    - 현재 구현 기준 잠금 시간은 10분

---

### 3.6 공통 필드

- **createdAt**
    - 생성 일시

- **updatedAt**
    - 수정 일시

---

## 4. 연관 관계

### Identity - Password (1:N)

- 하나의 Identity는 여러 Password를 가질 수 있다
- 비밀번호 변경 시 이력을 남기기 위해 리스트 형태로 관리

---

## 5. 설계 의도

- 비밀번호를 Identity 단위로 분리하여 관리
- 비밀번호 변경 이력을 저장하여 보안 정책 적용 가능
- 로그인 실패 및 계정 잠금 기능을 지원
- 다양한 암호화 알고리즘 지원 가능

---

## 6. 주요 시나리오

### 6.1 일반 로그인

- 최신 Password 기준으로 인증 수행
- passwordHash 비교로 로그인 검증

---

### 6.2 비밀번호 변경

- 새로운 Password 레코드 생성
- 이전 비밀번호는 이력으로 유지

---

### 6.3 로그인 실패

- failCount 증가
- 5회 연속 실패 시 lockedUntil 설정

---

### 6.4 계정 잠금

- lockedUntil 이전까지 로그인 차단
- 시간 경과 후 자동 해제

---

## 7. 고려 사항

- passwordHash는 반드시 안전한 해시 알고리즘 사용 필요
- passwordAlgo를 저장하여 알고리즘 변경 대응 가능
- 로그인 성공 시 failCount와 lockedUntil을 초기화한다
- 현재 계정 잠금 기준은 5회 실패, 10분 잠금이다
- 비밀번호 재사용 방지 정책 적용 가능

---

## 8. 향후 확장

- 로그인 시도 이력과 연계한 보안 강화
