# LoginHistory 엔티티

## 1. 개요

LoginHistory는 사용자의 로그인 시도 이력을 기록하는 엔티티이다.  
성공/실패 여부, 로그인 방식, 접속 환경 등의 정보를 저장하여 보안 및 운영 분석에 활용한다.

---

## 2. 테이블 정보

- 테이블명: `login_history`
- 설명: 사용자 로그인 시도 이력 관리

---

## 3. 필드 정의

### 3.1 기본 식별 정보

- **id**
    - 로그인 이력 고유 식별자
    - PK

- **userId**
    - 로그인 시도 대상 사용자 ID
    - User 엔티티와 직접적인 연관 관계는 없음 (히스토리 데이터)
    - 탈퇴 사용자도 추적 가능

---

### 3.2 로그인 정보

- **providerType**
    - 로그인 제공자 유형
        - `LOCAL` (일반 로그인)
        - `KAKAO`
        - `GOOGLE`

```java
public enum ProviderType {
    LOCAL,    // 일반 로그인
    KAKAO,    // 카카오
    GOOGLE   // 구글
}
```
---

### 3.3 결과 정보

- **attemptResult**
    - 로그인 시도 결과
    - 예
        - `SUCCESS`
        - `FAIL`

- **failReason**
    - 로그인 실패 사유
    - 예:
        - 비밀번호 불일치
        - 계정 잠금
        - 인증 실패
    - 성공 시 null 가능

---

### 3.4 접속 환경 정보

- **clientIp**
    - 사용자 접속 IP 주소

- **userAgent**
    - 사용자 브라우저/디바이스 정보

---

### 3.5 공통 필드

- **createdAt**
    - 로그인 시도 시각

---

## 4. 연관 관계

- User와 직접적인 연관 관계를 가지지 않는다
- userId만 저장하여 히스토리 데이터로 관리한다

---

## 5. 설계 의도

- 로그인 성공/실패 이력을 모두 기록하여 보안 분석 가능
- 탈퇴한 사용자도 이력 추적 가능
- User 엔티티와 분리하여 데이터 변경 영향 최소화
- 접속 환경 정보를 기반으로 이상 징후 탐지 가능

---

## 6. 주요 시나리오

### 6.1 로그인 성공

- attemptResult = SUCCESS
- failReason = null

---

### 6.2 로그인 실패

- attemptResult = FAIL
- failReason 기록

---

### 6.3 보안 분석

- 특정 IP에서 반복 로그인 시도 탐지
- 로그인 실패 횟수 기반 차단 정책 활용

---

## 7. 고려 사항

- attemptResult, providerType은 Enum으로 관리 권장
- failReason은 코드 기반 관리가 바람직
- clientIp, userAgent는 길이 및 저장 정책 고려 필요
- 대용량 데이터 발생 → 파티셔닝 또는 아카이빙 전략 필요
- 개인정보 보호 정책에 따른 로그 보존 기간 설정 필요

---

## 8. 향후 확장

- 로그인 위치(GeoIP) 정보 추가
- 위험도 점수(Risk Score) 계산
- 이상 로그인 탐지 시스템 연동
