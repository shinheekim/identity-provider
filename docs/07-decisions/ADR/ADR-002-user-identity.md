# ADR-002 User / Identity 구조 분리

## 상태
완료.

## 배경
일반 로그인과 소셜 로그인을 함께 지원해야 하는 요구사항이 존재했다.  
단일 User 테이블에 로그인 정보를 포함할 경우 확장성이 떨어지는 문제가 있었다.

---

## 결정
User와 Identity를 분리하는 구조를 채택한다.

---

## 이유

- 하나의 사용자(User)가 여러 로그인 수단(Identity)을 가질 수 있음
- 소셜 로그인 확장 (카카오, 구글 등)에 유리
- 로그인 방식 변경 시 영향 범위 최소화
- 도메인 책임 분리가 명확해짐

---

## 대안

### 1. User 단일 구조
- 로그인 정보와 사용자 정보가 결합됨
- 소셜 로그인 확장 시 구조 복잡도 증가

---

## 영향

- Identity 테이블 추가 필요
- 로그인 로직이 Identity 중심으로 변경됨
- API 및 DB 설계 복잡도 증가 (하지만 확장성 확보)
